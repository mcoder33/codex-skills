# Смысл метрик и дизайн

## Контракт метрики

Для изменяемых показателей установи:

| Часть | Что требуется выяснить |
| --- | --- |
| Источник | Datasource, поле или выражение, наблюдаемая сущность |
| Объект счёта | Записи журнала, запросы, события, уникальные пользователи, partition и т. п. |
| Единица | События, запросы/с, байты, миллисекунды; преобразования единиц |
| Время | Timestamp события/наблюдения, окно, bucket, часовой пояс, ожидаемая свежесть |
| Выборка | Фильтры, labels, ключи группировки, ожидаемое покрытие |
| Агрегация | Count/sum/avg/max/last/rate; почему она соответствует типу данных |
| Состояния | Что означают 0, null, no-data, unknown, stale и reset |

Достаточно компактной записи рядом с рабочими артефактами; для маленькой правки не создавай отдельный трактат. Существенные ограничения интерпретации должны быть видны в названии, единицах или кратком описании панели.

HTTP 200 подтверждает приём запроса на наблюдаемой границе. Он не доказывает дальнейшую доставку, отправку СМС или другой бизнес-результат. Счётчик HTTP-ошибок может не включать сетевые сбои без ответа. Количество log rows не равно количеству уникальных событий или людей: учитывай повторы, retries и разные временные окна.

Разность входного и выходного счётчиков нельзя назвать потерями или процентом потерь без контракта корреляции, дедупликации и окна завершения. Не придумывай SLA и целевые пороги. Ноль записей об ошибках не даёт зелёный общий статус при отсутствии данных о работе.

## Время и область фильтров

Для каждой панели различай текущее состояние, последнее наблюдение в выбранном диапазоне и худшее значение за период. Подпись «сейчас» требует свежего наблюдения; исторический максимум не становится текущим после `lastNotNull`. При bucket max → last получается максимум последнего непустого bucket, а не обязательно последнее измерение.

Различай timestamp измерения, экспорта и поступления в хранилище. Свежая доставка старого снимка не доказывает свежесть состояния. Покажи возраст измерения; допустимую задержку и часы источника сверяй с контрактом сбора, без придуманного общего порога.

Для переменных составь компактную карту «фильтр → какие панели и сущности он ограничивает». Панель общего ресурса может намеренно не зависеть от выбранной базы; обозначь это в её названии или описании. Подпись «все базы» недопустима, если выборка неполна. Нельзя автоматически связывать базу и службу без подтверждённого соответствия.

Проверь одно значение, несколько и All, включая значения с пробелами или специальными символами, если они допустимы. Формат интерполяции выбирай по языку запроса: Lucene escaping и Prometheus/LogQL regex не взаимозаменяемы. Проверяй подставленный запрос, состав объектов и результат.

## Снимки состояния и таблицы

Повторяющиеся gauge snapshots нельзя складывать по наблюдениям: число точек зависит от частоты сбора. Для временного bucket выбирай осмысленный avg/max либо другое обоснованное представление; для текущего состояния бери последнее наблюдение по ключу и показывай его timestamp/свежесть.

В клиентских transformations типовой вариант — sort timestamp ASC → groupBy → last. Проверь фактическую семантику своей версии. `lastNotNull` недопустим, если новый null означает неизвестное состояние: он вернёт устаревшее число. Значение, статус и timestamp должны относиться к одному наблюдению; независимые редукции полей не должны собирать вымышленную строку. Особенно проверь отсутствующие поля и неоднородные записи; если transformations не сохраняют связь, сформируй последнюю запись на стороне источника.

Запрос снимков должен сохранять error/unknown rows до выбора последнего наблюдения. Фильтр наличия необязательного числового поля может отбросить новый ошибочный снимок без этого поля и оставить старое «здоровое» значение даже при правильном sort → last. Проверяй последовательность good → bad с отсутствующими полями, а не только одиночные normal/empty выборки.

Независимые `max(WAL)` и `min(active)` за окно могут описывать разные моменты. Для таблицы текущего состояния выбирай целую последнюю запись по устойчивому ключу; исторические экстремумы выводи отдельно и называй соответствующим образом. Не включай изменяемый статус в ключ идентичности объекта: иначе старое и новое состояния станут разными строками.

Raw limit ограничивает число наблюдений и не гарантирует покрытие всех ключей. «Последний снимок каждого ключа» требует проверки полноты и когерентности выборки. Если это не доказано, допустимый промежуточный результат — явно названный журнал последних наблюдений с timestamp и указанным ограничением, без обещания текущего состояния всех объектов.

Диагностические таблицы выводят разрешённый список полей. Не показывай сырые payload, секреты, персональные данные или произвольные массивы только потому, что datasource умеет их вернуть.

## Kafka: читать только при Kafka-панелях

- Lag имеет идентичность cluster/topic/group и складывается по partition только с учётом полноты покрытия. Повторные exporter instances не должны удваивать сумму. Отсутствующие partition не превращай в нули.
- Неопределённый committed offset (в том числе -1), отсутствие offsets и частичное покрытие означают unknown. Значение lag=0 требует измеренных валидных позиций.
- Offset — gauge: скорость вычисляй по изменению за реальное elapsed time с явно описанным окном; `rate` предназначен для counters. Проверяй reset, изменение partition и разрыв сбора, чтобы они не создавали ложный spike. Конкретный алгоритм сверяй с поведением источника.
- Пустой topic с валидными нулевыми end offsets может иметь измеренную скорость 0. Это отличается от отсутствия измерения. Отсутствие group metrics не означает 0.
- Готовность коллектора или ответ exporter не равны Kafka readiness, возможности читать нужный topic либо успеху бизнес-цепочки. Подписывай именно наблюдаемую границу.

## Визуальная иерархия

Главный экран должен быстро отвечать на вопросы аудитории: понятные названия, единицы и акценты, мало вводного текста. Выбери компоновку по задаче и реальному viewport пользователя, а не по универсальной сетке. Технические детали можно раскрывать постепенно; множество равнозначных кнопок не решает перегрузку.

На первом экране проверь, читаются ли ключевые заголовки без обрезки, видны ли единицы и область показателя. Для таблиц проверь доступность важных колонок при обычной ширине, для графиков — различимость серий и доступность легенды. Не требуется помещать всю диагностику в один viewport.

Большие заливки нормального состояния могут заглушать предупреждения. Выбирай нейтральный фон или меньшие цветовые акценты там, где это улучшает приоритет внимания; зелёный оставляй для подтверждённого нормального состояния.

Используй цвет со смыслом и подписью, без зависимости только от цвета. Согласуй шкалы сопоставляемых графиков; не создавай ложное сравнение рядов с разными объектами или окнами. Gauge и pie применяй, когда их форма помогает конкретному решению. Не придавай измеренному нулю статус здоровья без основания.
