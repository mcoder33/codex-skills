# Механика Grafana

Ниже наблюдения из Grafana 11.6 с classic dashboard JSON (v1). Для другой версии, datasource plugin или схемы v2 сначала проверь актуальный контракт и реальные ответы. Не применяй эти приёмы как универсальные обходы.

## Структура и API

- В classic JSON panel IDs уникальны во всём дашборде, включая вложенные панели свёрнутых rows. `refId` уникален среди targets одной панели; между панелями его можно повторять. В одном batch `/api/ds/query` каждому запросу нужен отдельный `refId`.
- Сохраняй wrapper и поля, требуемые конкретным API/tool: UID, folder, version и overwrite имеют разные уровни. Не переноси JSON между API без проверки схемы.
- MCP-ответ может содержать JSON в `content[].text`; сначала распакуй фактический ответ. У наблюдавшегося `grafana_api_request` jq-фильтр применялся к HTTP body: `.results`, а не `.data.results`. Это зависит от инструмента.
- HTTP 200 у query API может содержать ошибки отдельных запросов или пустые frames. Проверь error/status внутри результатов, schema, значения и timestamp.

## Временной диапазон панелей

В документации Grafana относительный override панели не действует при абсолютном диапазоне дашборда. Поэтому карточку «за 5 минут» проверь и с `now-6h → now`, и с фиксированными from/to; не считай `timeFrom` безусловным ограничением запроса. Сверь фактически отправленные границы и подпись. Если исторический выбор меняет смысл «сейчас», покажи это пользователю или выбери поддерживаемый механизм с явной семантикой.

При ручном вызове query API передавай эффективное окно панели: диапазон всего дашборда сам по себе не воспроизводит panel overrides. Renderer и query API должны проверять сопоставимые окна, timezone и интерполяцию переменных.

Источник: [Grafana query options](https://grafana.com/docs/grafana/latest/visualizations/panels-visualizations/query-transform-data/). Поведение установленной версии проверяй фактически.

## Elasticsearch и transformations

- Terms по известному полю журнала позволял агрегировать одно значение за диапазон; варианты без bucket или только с filters в наблюдавшейся среде возвращали пустые frames. Это повод проверить результат, а не запрещать эти запросы везде.
- Имена после groupBy могут стать `field(last)` или `field (last)`. Сначала прочитай фактические frame fields, затем настраивай organize, overrides и mappings. Сверь результат renderer.
- Комбинация Stat displayName и regex в `reduceOptions.fields` может исключить все числовые поля. Валидный JSON и заполненный source frame не доказывают, что Stat отрисует число.
- Поддержка limit для raw data и transformations зависит от версии/плагина. Проверяй фактическое ограничение результата; не полагайся на неизвестное поле в JSON.
- Подмена no-data нулём допускается только по контракту метрики; mappings не должны скрывать неизвестность и устаревание.

## Renderer

Для абсолютного диапазона `get_panel_image` в наблюдавшемся инструменте работали строковые epoch milliseconds; ISO-строки были неверно преобразованы и дали диапазон около 1970 года. Проверь отображённый диапазон, timezone и единицы timestamp независимо от успешного ответа renderer.

Проверенный custom unit для таблицы времени: `time:DD.MM.YYYY HH:mm:ss`. Стандартный date unit может локализоваться иначе, включая английские подписи. Выбор формата сверяй с аудиторией и текущей версией.
