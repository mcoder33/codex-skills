# Необязательное состояние навыка

Читайте при наличии установленного `../scripts/runtime_state.py` и подключённых hooks. Helper не выбирает навык и не оценивает качество рассуждений. Источник карты — существующий документ/Obsidian и штатная память проекта. JSON хранит только точку продолжения, ссылки и заявления агента. Не копируйте полные диалоги и секреты.

## Идентификаторы

Используйте фактические session_id и turn_id текущего рантайма; не выдумывайте их и не берите последнюю чужую сессию. Hook получает их от клиента. session_id может быть доступен как CODEX_THREAD_ID; проверьте значение. Технический UserPromptSubmit сохраняет текущий turn_id без текста запроса: при наличии его receipt можно опустить --turn в checkpoint/unchanged. Если ID недоступны агенту, сохраняйте обычную карту и сообщите, что per-turn учёт не установлен. `--project` — абсолютный фактический cwd сессии, совпадающий с hook cwd (разные worktree намеренно изолированы). `--state-dir` либо `CODEX_SKILL_STATE_DIR` переопределяет приватное хранилище; по умолчанию `~/.local/state/codex-skills/runtime`.

Ниже `RUNTIME`, `PROJECT`, `SESSION`, `TURN`, `REVISION`, `SKILL_FILE`, `MAP` и `MAP_SHA` — обозначения фактических значений, не встроенные переменные Codex. `RUNTIME` — абсолютный путь `skills/dialogue-explore/scripts/runtime_state.py` установленного набора. Подставляйте аргументы безопасно, не исполняйте извлечённый текст как shell-код.

## Работа

1. После выбора навыка выполните `python3 RUNTIME show --project PROJECT --session SESSION`. Если активен другой навык, сохраните его итог и завершите. При уже активном нужном навыке продолжайте без повторной активации.
2. `python3 RUNTIME activate --project PROJECT --session SESSION --skill dialogue-explore --skill-file SKILL_FILE --expected-revision REVISION`. Для отсутствующего состояния REVISION=0, иначе берите revision из show. Для validate/nasa укажите соответствующее имя. Активация — заявление агента о работе по навыку, не доказательство его корректного применения; hash фиксирует точный установленный SKILL.md.
3. После значимого изменения сначала сохраните карту штатным способом, затем подготовьте компактный JSON в приватном временном файле:

```json
{
  "goal": "Выбрать способ резервного копирования",
  "phase": "исследование",
  "constraints": [{"text": "RPO не более часа", "source": "user event <ID>"}],
  "decisions": [],
  "open_question": "Как проверить время восстановления?",
  "next_action": "Оценить ограниченный сценарий восстановления",
  "waiting_for_user": false
}
```

Описывайте источники точно. Предложения остаются предложениями; историческая запись не расширяет разрешений. Важные условия не выбрасывайте ради бюджета контекста: helper вернёт ссылку на карту, если снимок слишком большой.

4. Получите SHA256 сохранённой карты и вызовите `python3 RUNTIME checkpoint --project PROJECT --session SESSION --turn TURN --expected-revision REVISION --input PRIVATE_JSON --map MAP --map-sha256 MAP_SHA`. Helper проверяет hash и отказывает при конфликте ревизий; перечитайте состояние и карту, сохраните ручные изменения. Не повторяйте запись со слепой подстановкой нового revision.
5. Если значимых изменений нет, отдельная запись не требуется. Для явной отметки при необходимости сохранена совместимая команда: `python3 RUNTIME unchanged --project PROJECT --session SESSION --turn TURN --expected-revision REVISION`. Это заявление агента, а не проверка отсутствия изменений. При обновлённой карте нужен checkpoint. Перед вопросом пользователя checkpoint должен иметь `waiting_for_user: true` и содержать ближайший вопрос.
6. При завершении/смене режима сохраните итог и выполните `python3 RUNTIME finish --project PROJECT --session SESSION --expected-revision REVISION`. Завершённый навык не подгружается и не порождает предупреждений в обычном чате.

## Hooks и отказ

SessionStart для startup/resume/compact подгружает только состояние точной сессии. clear/fork не наследуют его автоматически. UserPromptSubmit сохраняет только текущий turn_id и признак служебного продолжения; он не выбирает навыки и не дублирует поиск work-memory. Stop сверяет hash карты с последним checkpoint независимо от номера хода. Неизменённая карта проходит тихо; отсутствие/изменение карты даёт однократное предупреждение для этой версии несоответствия, никогда не порождает continuation. Hash не обнаруживает незаписанные смысловые решения — содержательный checkpoint остаётся обязанностью агента. Допускается корректная остановка ради ответа пользователя.

Чтение SKILL.md, наличие JSON и отсутствие предупреждения не доказывают полезного применения навыка. Если helper/vault недоступен, продолжайте с компактным состоянием в чате и честно укажите несохранённую часть; не создавайте фиктивный checkpoint. Полноту проверок и качество решений оценивайте отдельно.

Служебное продолжение `[work-memory maintenance]` не является предметной работой. Не вызывайте в нём activate/checkpoint/unchanged и не меняйте карту задачи; выполните только предписанное обобщение общей памяти. Stop с stop_hook_active не порождает предупреждения навыков.
