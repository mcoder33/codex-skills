# Структура сервиса и жизненный цикл

Читать при сборке зависимостей, transport boundaries, нескольких процессах,
контейнеризации или пересечении функциональных веток. Не инициирует миграцию инфраструктуры.

## Архитектура по реальным границам

Ardan Labs service показывает явную сборку, transport/app/business/foundation и
предметные пакеты. Это один пример. Названия `api`, `app`, `business`, `foundation`,
`zarf`, расположение stores и число бинарников не являются универсальными требованиями.
Сначала объясни владельцев данных и направленные зависимости, потом выбирай дерево.

Composition root создаёт ресурсы и связывает concrete adapters со сценариями. Простой
`main → run → constructors → serve → shutdown` обычно достаточен. Конфигурация и I/O
не должны скрываться в package init или бесформенном global registry без причины.
Конструктор, который открывает сеть/запускает goroutines, требует ясного lifecycle и rollback
при частично неуспешной сборке. Не добавлять DI container ради нескольких вызовов.

Бизнес-правила не зависят от HTTP handler или concrete SQL implementation. Wire encoding,
SQL projection и orchestration имеют своих владельцев. Технически общий код не обязательно
универсален: общий продуктовый envelope и нормализация предметных полей остаются контрактом
продукта. Не складывай их в `foundation`/`utils`, чтобы убрать циклический импорт.

Не дроби транзакционную согласованность по каталогам/таблицам. Общий storage adapter
может быть оправдан несколькими связанными сценариями. Audit/trace/cache decorator
полезен для реальной сквозной задачи; не превращай каждую операцию в цепочку обёрток.

Общий бинарник с ролью и несколько binaries — оба допустимы. Выбор по независимости
обновления, ресурсов, конфигурации и пользователя. Если выбраны роли, загружай только
их настройки/ресурсы. Отдельные процессы не обязывают создавать отдельные Go modules;
один binary содержит код обеих ролей даже при запрещённых cross-imports.

## Параллельные ветки и переносы

Сверь живые SHA, MR diff и dirty worktrees. Описание MR/старый CI могут отставать от
локальной работы. Чужие рабочие каталоги не переключать, не очищать и не коммитить.
Сначала определи владельцев общих контрактов и зависимых изменений; разделение файлов
не гарантирует независимости. WIP не становится принятым контрактом по наличию на диске.

В своей разрешённой области сохраняй намерения обеих сторон. Проверь decoder/producer,
ошибки, ACK/commit, config/build и тесты совместно. Проверки отдельных HEAD не доказывают
совмещённый результат. При переезде пакетов обновляй Docker COPY, scripts, генераторы,
imports, CI и активную карту кода. Сохраняй тесты бизнесового контракта при удалении старого
механизма. Процедура перехода данных — отдельная работа, не побочный эффект rename.

## Готовность Go-процесса к контейнеру

Изолируемые настройки, stdout/stderr, явный lifecycle, probes и resource budgets
упрощают перенос. Красивое дерево каталогов этого не доказывает. Наличие Kubernetes
в учебном starter kit не означает, что он нужен текущему проекту.

Если Kubernetes действительно входит в поручение:
- Используй существующие механизмы поставки, а не добавляй Helm/operator автоматически.
- Разделяй Deployment/Service по runtime-ролям, когда нужны независимые ресурсы и lifecycle.
  Kafka/БД не требуется переносить в кластер вместе с приложением.
- Startup, readiness и liveness проверяют разные состояния. Отказ внешней зависимости
  не должен без причины запускать liveness restart loop. Readiness исключает HTTP endpoint
  из обычной Service-маршрутизации, но сама не останавливает consumer фоновой очереди.
- SIGTERM/drain/join и termination grace образуют один бюджет; preStop тоже расходует его.
  Потерянный ACK и повтор после restart сохраняют прежний контракт доставки.
- Суммарные DB pools/concurrency/память растут с replicas. Partition count и downstream
  capacity ограничивают полезное масштабирование. HPA не исправляет неограниченный backlog.
- Resource requests/limits опираются на измерение; reservation queue bytes не равна RSS.
- Пилот в новом локальном окружении выполняется с явно выбранным context и синтетическими
  зависимостями. Render/validate не равны runtime proof; старый cluster context не разрешение
  применить туда манифесты.
- Первый несовместимый переход схемы/очереди нельзя подменять обычным rolling update или
  автоматическим rollback. Deployment readiness, broker ACK и business outcome различаются.

Создание кластера, переключение трафика и production-операции требуют действующего поручения.
Обычная Go-правка не становится Kubernetes-проектом из-за применения этого навыка.
