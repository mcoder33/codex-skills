# Источники и выбор приёмов

Эти материалы исследованы 16 октября 2026. Они поддерживают отдельные элементы рабочего подхода; комбинация навыка и точность его прогнозов ещё требуют практической проверки. При новом вопросе о содержании или актуальности первоисточника открой соответствующий документ.

| Когда полезно | Приём и перенос | Первичный источник |
|---|---|---|
| Нужна общая структура решения | Ожидания, требования, логическая модель, проект; итеративное согласование частей | [NASA System Design](https://www.nasa.gov/reference/4-0-system-design-processes/) |
| Нужно связать реализацию с исходной целью | Соответствие установленным требованиям и пригодность для ожидаемого использования проверяются отдельно | [NASA Verification](https://www.nasa.gov/reference/5-3-product-verification/), [Validation](https://www.nasa.gov/reference/5-4-product-validation/) |
| Функциональность ясна, качество сформулировано расплывчато | Сценарии качества до архитектуры; оценка рисков и компромиссов выбранной архитектуры | [SEI QAW](https://www.sei.cmu.edu/library/quality-attribute-workshops-qaws-third-edition/), [ATAM](https://www.sei.cmu.edu/library/architecture-tradeoff-analysis-method-collection/) |
| План зависит от важных предположений | Выявить уязвимые допущения, признаки их нарушения и варианты реакции | [RAND Assumption-Based Planning, применение](https://www.rand.org/content/dam/rand/pubs/monographs/2007/RAND_MG532.pdf) |
| Неясно, что исследовать следующим | Определять очередной цикл по существенному риску и соразмерной проверке | [Boehm / SEI Spiral Development](https://insights.sei.cmu.edu/documents/5439/2000_003_001_13655.pdf), [NASA Decision Analysis](https://www.nasa.gov/reference/6-8-decision-analysis/) |
| Есть несколько объяснений проблемы | Обновлять рабочие гипотезы по свидетельствам и оценивать достаточность информации для действия | [National Academies: The Diagnostic Process](https://www.nationalacademies.org/read/21794/chapter/4) |
| Технически допустимые варианты по-разному подходят человеку | Разделять уверенность в доказательствах, последствия выбора и предпочтения | [GRADE](https://www.gradeworkinggroup.org/), [NICE Shared Decision Making](https://www.nice.org.uk/guidance/ng197/chapter/recommendations) |
| Решения теряются при реализации или пересмотре | Сохранить контекст, выбор, статус и последствия; проверять нужные архитектурные свойства | [Исходное описание ADR](https://www.cognitect.com/blog/2011/11/15/documenting-architecture-decisions), [Thoughtworks fitness functions](https://www.thoughtworks.com/en-us/radar/techniques/dependency-drift-fitness-function) |
| Нужно найти слабую связь плана | Проиграть конкретный неблагоприятный сценарий и выделить проверяемые последствия | [War-Gaming, статья практика](https://home.army.mil/wood/9317/5691/4948/Shuler.pdf) |
| Возникает экспертная догадка | Искать узнаваемые закономерности и проверять качество обратной связи; субъективная уверенность не доказывает точность | [Kahneman и Klein, 2009](https://pubmed.ncbi.nlm.nih.gov/19739881/) |

Границы переноса:

- Не называй нашу оценку кода применением GRADE и не переноси клинические пороги на программирование.
- Военная статья описывает авторскую практику, а не обязательную доктрину. Прогон сценария не даёт измеренной вероятности успеха.
- Историческая заметка Thoughtworks раскрывает идею проверок; её рекомендации об инструментах не считаются автоматически текущими.
- QAW/ATAM помогают сформулировать и исследовать качество; они не гарантируют, что реализация ему соответствует.
- Формула вероятности результата по времени обсуждения в навык не заложена. Обоснованность прогноза проверяется по сохранённым прогнозам и фактическим исходам сопоставимых задач.
