# Codex Skills

Десять переносимых навыков для Codex: общение и обсуждение решений, связная разработка, выбор модели и передача исполнения, статистика делегации и ограниченное улучшение инструкций. Карта обсуждения хранится в обычных Markdown-заметках Obsidian. Основной язык — русский.

## Что входит

| Часть | Когда использовать |
| --- | --- |
| `grafana-dashboards` | Создать или улучшить дашборд Grafana: проверить смысл метрик, временные окна, фильтры, свежесть и отображение. |
| `adaptive-dialogue` | Подстраивать тон, подробность и темп по предпочтениям и обратной связи; может работать как постоянное руководство по общению. |
| `dialogue-explore` | Проблема ещё не ясна: один существенный узел диалога, ответ пользователя, следующий шаг до плана. |
| `dialogue-validate` | План уже есть: проверить основания, зависимости, альтернативы и пропущенные сценарии. |
| `nasa` | Связать ожидаемый результат, архитектурные ограничения, решения, допущения и проверки; оценить готовность плана к исполнению. |
| `model-router` | Главный агент выбирает модель и ограниченный контракт для содержательной работы. |
| `execute-handoff` | По команде «делай» предложить модель и reasoning, передать согласованную задачу и проверить результат. |
| `go-development` | Go-разработка и ревью: связные операции, данные, границы пакетов, конкурентность и проверяемое поведение. |
| `delegation-stats` | Собрать локальную статистику делегирования и показать её в Obsidian. |
| `session-retrospective` | Ограниченно улучшать два dialogue-навыка при отдельном разрешении и проверках. |

Навыки общения, разработки и выбора исполнителя в `skills/` имеют UI-метаданные; общий контракт двух dialogue-навыков лежит внутри dialogue-explore, а `nasa` содержит собственный шаблон инженерной карты. `agents/` содержит четыре резервных профиля. `config/` содержит фрагменты для ручного слияния, а `vault-template/` — связанный вымышленный пример. Личных диалогов, настроек аккаунта, секретов и исследовательских архивов нет.

## Установка

Нужны Codex с навыками и поддержкой пользовательских агентов, Obsidian для просмотра графа; для проверок ниже — Python 3.11+. Возможности, имена моделей и доступность effort различаются по версии клиента, аккаунту и среде. Сначала проверьте их в своей среде. Эти файлы сами по себе не включают отсутствующую поддержку агентов.

Установка ручная: сначала сделайте резервные копии затрагиваемых файлов. Команды выполняются из корня этого репозитория. Пути ниже — примеры для своего домашнего каталога. Используйте фактическое расположение config.toml и AGENTS.md вашего клиента, если оно отличается.

```sh
KIT_HOME="${CODEX_HOME:-$HOME/.codex}"
DIALOGUE_VAULT="$HOME/Documents/Obsidian/Codex-Dialogue"
```

1. Создайте `KIT_HOME/skills` и `KIT_HOME/agents`, если их нет. Скопируйте выбранные каталоги из `skills/` в `KIT_HOME/skills` (для полного набора — все десять), а при использовании маршрутизатора — четыре TOML из `agents/` в `KIT_HOME/agents`. **Если одноимённые файлы или каталоги уже есть, сначала сравните их и сохраните копии; не выполняйте слепую замену.** Оба dialogue-навыка устанавливаются вместе: validate использует `../dialogue-explore/references/discussion-map.md`.
2. Откройте существующий `KIT_HOME/config.toml`. Слейте с ним [config/agents.toml](config/agents.toml), сохранив остальные разделы. Для каждого существующего `agents.routed-*` объедините ключи в одной таблице. Не дублируйте таблицы и ключи. Существующий `[agents]`, его лимиты и чужие профили сохраняются; не вставляйте второй `[agents]`. При inline-таблицах сначала приведите эту область к допустимому TOML. Пути `config_file` относительны к каталогу config.toml; проверьте их на своей версии клиента.
3. В [config/AGENTS.fragment.md](config/AGENTS.fragment.md) замените `{{CODEX_HOME}}` на абсолютный KIT_HOME и `{{DIALOGUE_VAULT}}` на абсолютный путь vault. Добавьте только этот блок в существующий `KIT_HOME/AGENTS.md`, сохранив остальные инструкции. Для постоянной адаптации общения также добавьте [config/adaptive-dialogue.fragment.md](config/adaptive-dialogue.fragment.md), заменив `{{CODEX_HOME}}` на абсолютный KIT_HOME. При повторе заменяйте соответствующий блок между BEGIN/END, а не добавляйте второй. Эти обозначения не являются автоматической интерполяцией Codex. Проверьте, что блоки действительно читаются выбранным клиентом.
4. Создайте выбранный каталог vault и перенесите содержимое `vault-template/`. Для существующего vault добавляйте только отсутствующие заметки; при совпадении имён сливайте вручную и сохраняйте пользовательские ссылки. Не копируйте шаблон поверх реальных обсуждений.
5. В Obsidian выберите «Open folder as vault» / «Открыть папку как хранилище», укажите этот каталог, откройте `Карта обсуждений`, затем Graph view / «Граф». В примере шесть заметок с реальными связями; граф различает связи, а статусы читаются в заметках. Цветовые группы можно настроить вручную.
6. Убедитесь, что Codex обнаруживает выбранные навыки (девять при полной установке) и установленные профили (четыре для маршрутизатора). Если клиент не перечитал настройки, откройте новый сеанс либо перезагрузите клиент согласно его версии. Проверьте эффективную модель на небольшом разрешённом задании. Загрузка TOML не доказывает фактический запуск выбранной модели.

Проверка синтаксиса после слияния (подставьте тот же KIT_HOME):

```sh
python3 - "$KIT_HOME/config.toml" <<'PYCODE'
import pathlib, sys, tomllib
config = pathlib.Path(sys.argv[1])
data = tomllib.loads(config.read_text())
for name in ('routed-scout', 'routed-worker', 'routed-reviewer', 'routed-expert'):
    profile = config.parent / data['agents'][name]['config_file']
    tomllib.loads(profile.read_text())
print('TOML и пути профилей проверены; запуск модели отдельно не проверен.')
PYCODE
```

## Адаптация общения отдельно от набора

[adaptive-dialogue](skills/adaptive-dialogue/SKILL.md) можно установить самостоятельно: скопируйте `skills/adaptive-dialogue` в каталог навыков клиента, предварительно сравнив существующую версию. Obsidian, профили агентов, Python, hooks и остальные навыки для него не обязательны.

Для включения во всех проектах добавьте в глобальный `AGENTS.md` только [блок адаптации](config/adaptive-dialogue.fragment.md), заменив `{{CODEX_HOME}}` на фактический абсолютный путь каталога настроек. Сохраните другие инструкции. Если клиент использует `AGENTS.override.md`, добавьте блок в действительно загружаемый файл; не создавайте новый override ради установки. Начните новый сеанс и проверьте, что клиент видит блок и установленный навык. В уже открытых сеансах перечитывание зависит от клиента. Проектные инструкции и текущие просьбы могут уточнять стиль.

Разовый вызов без глобального включения:

```text
$adaptive-dialogue Учитывай мои предпочтения и постепенно подстраивай
манеру общения по обратной связи, сохраняя точность и своё суждение.
```

Навык различает явные предпочтения, предварительные наблюдения и временную ситуацию. Использует существующую разрешённую память, если она есть; без неё работает в текущем диалоге. Установка сама не создаёт память и не гарантирует извлечение предпочтений в каждом новом чате. История и личные профили остаются в вашем хранилище, в этот репозиторий их копировать не нужно.

Проверить границы помогают [вымышленные сценарии](skills/adaptive-dialogue/references/examples.md): временная просьба о краткости, поправка про юмор, цитата из лога, недоступная память и несогласие по фактам. Реальную пользу оценивайте по обычным разговорам и обратной связи. Для отката удалите только добавленный блок; каталог навыка удаляйте, только если в нём нет нужных локальных изменений. Сохранённые предпочтения не удаляются при удалении навыка.

## Инженерная карта с nasa

Для отдельной установки [nasa](skills/nasa/SKILL.md) достаточно скопировать каталог `skills/nasa` в каталог навыков клиента, предварительно сравнив существующую одноимённую версию, если она есть. Его собственные справочные файлы входят в этот каталог. Настройка профилей агентов для этого навыка не требуется. Путь к разрешённому vault укажите в текущих инструкциях или настройке `DIALOGUE_VAULT`, как описано выше; до этого карта может оставаться в чате.

Пример запуска:

```text
$nasa Разбери задачу добавления скидок в сервис заказов.
Построй инженерную карту, выясни существенные архитектурные ожидания
и покажи, что получится при передаче текущего плана в исполнение.
```

Навык связывает ожидания, требования, решения, допущения и проверки. Он различает неизвестный факт, невыясненное предпочтение и допустимый выбор исполнителя; отдельно отмечает основание, принятие решения и состояние проверки. Если обсуждение уже ведётся другими навыками, используйте ту же карту и ранее принятые решения.

В основе — адаптация NASA, SEI QAW/ATAM, RAND ABP и подходов к принятию решений из медицины. Первичные ссылки включены в [справочник](skills/nasa/references/sources.md). Это пилотный рабочий метод: счётчик вопросов не выдаётся за вероятность успеха, а время подготовки связывается с полученными свидетельствами. Эффективность на реальных задачах и точность прогнозов ещё предстоит проверить.

## Как работает маршрутизация

| Профиль | Запрошенная модель | Effort | Назначение |
| --- | --- | --- | --- |
| routed-scout | gpt-6-luna | high | Узкий сбор фактов, только чтение |
| routed-worker | gpt-6.1-sol | medium | Реализация в выделенных файлах |
| routed-reviewer | gpt-6.1-sol | high | Независимое ревью, только чтение |
| routed-expert | gpt-6-astra | low | Сложные противоречия, только чтение |

Это исходные имена профилей, а не обещание их доступности. Если модель отсутствует, сначала согласуйте доступное соответствие и обновите профиль и таблицу выбора навыка; не подменяйте модель молча. Учитывайте явный выбор пользователя. Уровень effort — глубина разбора, а не число файлов.

Главный агент ведёт разговор, планирование, координацию и карту. Исполнители работают по ограниченному контракту без рекурсивной делегации. Обязательные роли существующего workflow сохраняются. До трёх подагентов — выбранный предел набора, подчинённый реальному лимиту среды; зависимости выполняются последовательно. При недоступности делегирования агент сообщает ограничение. Эта политика основана на инструкциях и не является технической песочницей.

## Простой пилот

Попросите: «Используй $dialogue-explore: помоги выбрать формат небольшой учебной встречи». Ответьте на ближайший существенный вопрос; проверьте, что ответ изменил обсуждение и сохранился в карте. Затем: «Используй $dialogue-validate: давай проверим полученный план». После паузы попросите восстановить текущий вопрос по карте.

В новом обсуждении пример остаётся примером: создаётся отдельная тема. Проверяйте, что `proposed` не превратился в `confirmed` без явного решения, открытые вопросы не исчезли, мысленная проверка не названа фактическим результатом. Запишите версию навыка, конкретный эпизод и итог пилота. Успешный пилот или синтаксическая проверка не доказывают оптимальность маршрутизации и эффективность во всех задачах.

## Обновление и откат

Перед обновлением сохраните копии только затрагиваемых навыков, четырёх профилей, config.toml и AGENTS.md вне репозитория. Сравните новую версию с установленной. Обновляйте файлы навыков и профили с сохранением локальных правок; конфигурацию снова слейте вручную. Vault при обновлении не заменяйте шаблоном.

Для отката верните сохранённые версии файлов. Если после резервирования появились чужие изменения config.toml/AGENTS.md, отмените только строки этого набора вручную вместо полной замены. При первой установке без прошлых файлов удалите только добавленные профили, таблицы и блок BEGIN/END; новые навыки удаляйте лишь если в них нет ваших правок. Заметки vault сохраняйте — это данные обсуждений. Перечитайте настройки клиентом при необходимости.

## Границы

Пилотная эвристика не гарантирует оптимальный выбор модели. Согласие с планом отдельно от доказательства его работоспособности. Навыки не расширяют разрешения на прод, публикации, сообщения или внешние изменения. При недоступном vault состояние остаётся в чате, а обновление карты не заявляется. Граф не открывается автоматически от появления файла. Фонового наблюдения и синхронизации этот набор не настраивает.

Лицензия пока не выбрана; файл LICENSE не добавлен. Публичная доступность репозитория сама по себе не предоставляет отдельную лицензию на использование и распространение.

## Локальная статистика делегирования

Дополнительный навык [delegation-stats](skills/delegation-stats/SKILL.md) читает локальные Codex-события и создаёт Markdown-дашборд Obsidian: собственные и делегированные токены, модели, длительности ходов и связи агентов. Установите каталог навыка рядом с остальными; приватное состояние и реальные заметки остаются вне репозитория. Сбор запускается вручную или после существенной делегированной работы, без фонового процесса.

Фактические списания недоступны. Опциональный API-сценарий отделён от них и показывает покрытие исключений. Порядок запуска, формулы, приватность и ограничения описаны в [docs/telemetry.md](docs/telemetry.md).

## Ограниченное улучшение навыков

Дополнительный навык [session-retrospective](skills/session-retrospective/SKILL.md) готовит небольшие изменения только двух dialogue-навыков по завершённым сессиям. Автоприменение требует текущего разрешения пользователя, поведенческих проверок и независимого ревью. `nasa` и `model-router` в область автоизменений не входят. Установка сама не создаёт расписание и не разрешает правки. Порядок, проверки и откат описаны в [docs/retrospective.md](docs/retrospective.md).

## Передача по команде «делай»

Дополнительный навык [execute-handoff](skills/execute-handoff/SKILL.md) передаёт согласованную работу исполнителю с предложением модели и reasoning и проверкой результата. Скопируйте каталог в свой каталог навыков. Для режима с 30-секундным выбором по умолчанию пользователь должен явно разрешить этот режим: [фрагмент инструкций](config/execute-handoff.fragment.md) содержит именно такое разрешение и не предназначен для автоматического добавления без согласия. При согласованной установке замените `{{CODEX_HOME}}` фактическим абсолютным путём и слейте блок с существующим AGENTS.md, сохраняя другие инструкции.

Ожидание работает внутри активного хода при доступном приёме новых сообщений; завершённый ход не возобновляется фоновым таймером. [Сценарии проверки](skills/execute-handoff/references/scenarios.md) включают отмену, ранний выбор, недоступную модель и обязательные разрешения.


## Go Development

[go-development](skills/go-development/SKILL.md) — развитие `cohesive-development`
для Go: данные и работающий сценарий определяют пакеты/интерфейсы; операции
остаются законченными, путь чтения — понятным, поведение — проверяемым.
Справки по concurrency, тестам/profiling и lifecycle читаются только при необходимости.
Книга Ultimate Go Notebook и Ardan service учтены с ограничениями версий и контекста.

Для установки скопируйте `skills/go-development` в каталог навыков клиента.
При обновлении с `cohesive-development` сначала сохраните/сравните свою установленную
версию, затем установите новый каталог и удалите старый из каталога обнаружения навыков.
Это переименование, а не второй дублирующий skill. Сохраните пользовательские изменения.
Исторические отчёты могут сохранять старое имя.

Для применения по умолчанию добавьте [фрагмент](config/GO-DEVELOPMENT.fragment.md)
в AGENTS.md, заменив `{{SKILL_PATH}}` фактическим абсолютным путём к новому SKILL.md.
При миграции замените прежний блок `BEGIN/END COHESIVE DEVELOPMENT` новым
`BEGIN/END GO DEVELOPMENT`; не переписывайте остальные инструкции. Обновите активные
ссылки и `$cohesive-development` в своих workflows на `$go-development`. Обновление
файлов не гарантирует переиндексацию уже открытой сессии клиента.

Для явного запуска используйте `$go-development`. Обычная Go-правка не запускает
полный аудит, Kubernetes-пилот или profiling. Широкое поручение сохраняет карту
покрытия всего объёма. Сам навык не разрешает делегацию, merge или deployment.
Obsidian, специальные модели, внешние аккаунты и PDF книги для работы навыка не нужны.

Проверки и пределы0.3.0: [отчёт](docs/go-development-validation.md).

## Проверки репозитория

В main обязательны проверки структуры навыков, локальных ссылок и секретов. PR владельца из этой же репозитории автоматически включают squash auto-merge после зелёного CI. [Правила, локальные команды и ограничения](docs/repository-ci.md).

## Дашборды Grafana

[grafana-dashboards](skills/grafana-dashboards/SKILL.md) устанавливается отдельно копированием каталога навыка. Нужен доступ к Grafana JSON и данным; визуальная проверка требует UI или renderer. Навык поддерживает аудит без записи, содержит условную справку по PostgreSQL и сценарии проверки свежести, полноты и фильтров. Он не предоставляет доступ и не разрешает изменение инфраструктуры. [Проверки этой версии](docs/grafana-dashboards-validation.md).
