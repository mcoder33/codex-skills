# Внесение изменений

[К обзору](README.md)

Изменения оформляйте в отдельной ветке и PR. Опишите проблему, новое поведение и выполненные проверки. Примеры должны соответствовать файлам этой ветки.

## Структура навыка

Минимум — каталог `skills/<имя>/SKILL.md` с YAML frontmatter: `name`, совпадающим с именем каталога, и непустым `description`. Инструкция должна объяснять назначение, вход, порядок работы, результат и границы применения.

Справочники помещайте в `references/`, помощники — в `scripts/`, UI-метаданные — в `agents/openai.yaml`, если они нужны. Ссылки делайте относительными. Общий контракт dialogue-навыков находится в `skills/dialogue-explore/references/discussion-map.md`; учитывайте эту зависимость.

Обновляйте README и примеры при добавлении, переименовании или удалении навыка. Не документируйте незавершённые PR как выпущенную возможность. Изменение инструкции не должно молча расширять права на внешние действия или чтение личных журналов.

## Локальные проверки

Из корня репозитория, Python 3.11+:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r scripts/ci-requirements.txt
.venv/bin/python scripts/validate_repository.py structure
.venv/bin/python scripts/validate_repository.py links
.venv/bin/python -m unittest discover -s tests -v
git diff --check
```

Валидатор ссылок работает с отслеживаемыми файлами: добавьте новые файлы документации в index перед проверкой. Не добавляйте `.venv`, журналы и временные артефакты.

Проверка `links` не проверяет внешние URL и якоря `#…`: их нужно просмотреть отдельно. Изменения поведения дополнительно проверяйте на положительных и отрицательных сценариях. Тесты Python и наличие формулировок не доказывают улучшение поведения модели.

## Приватность и публикация

Примеры должны быть вымышленными. Не включайте секреты, домашние пути конкретного пользователя, частные адреса сервисов, реальные переписки, карты проектов и журналы Codex. Используйте шаблонные пути и объясняйте подстановки. Проверяйте diff, включая новые файлы.

В CI выполняются `Skill structure`, `Local links` и `Secret scan`. Сканер секретов обнаруживает известные шаблоны, но не гарантирует отсутствие любых приватных данных. [Подробности проверок и слияния](docs/repository-ci.md).

Недрафтовые PR владельца из этого репозитория подпадают под настроенное автоматическое squash-слияние после обязательных проверок. Для результата на просмотре используйте draft PR. Чужие и fork PR этим workflow не сливаются.

Лицензия пока не определена. Перед переносом чужих материалов проверьте права на использование и распространение.
