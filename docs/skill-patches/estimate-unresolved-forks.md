# Дополнение к навыку оценки: нерешённая развилка останавливает передачу задачи

Переносимый фрагмент для включения в существующий навык оценки задач. Это дополнение к его
проверке готовности, а не самостоятельный навык и не замена правил рабочего трекера.
Полный исходник стороннего навыка, внутренние адреса, задачи и данные проектов здесь не публикуются.

## Правило

Развилка — выбор между исходами, которые меняют поведение для пользователя, судьбу данных
или согласованный объём. Одинаковое число часов у альтернатив не устраняет этот выбор.

Перед завершением оценки проверь каждую развилку по существу: какой исход выбран, кем или
каким фактом он определён, на какую область распространяется ответ. Метка «закрыто» сама по
себе ничего не доказывает. Частичный ответ закрывает только отвеченную часть.

Обещания «согласуем на тестировании», «решим до релиза», назначенный ответственный, срок
и план «подготовить отчёт, затем утвердить карту» оставляют сам выбор нерешённым.
Готовый механизм получения решения не является решением. Нельзя переименовать вопрос в
«закрыто для оценки», «релизную зависимость» или риск, покрытый резервом часов, чтобы пройти проверку.

Если вопрос должен решать человек и содержательного ответа нет — остановись. До ответа:

- не записывай итоговую оценку и не переводи задачу в готовность к работе;
- не предлагай и не запускай передачу этой задачи в декомпозицию, реализацию или релиз;
- не выдавай предварительный диапазон часов за окончательную оценку или разрешение двигаться дальше;
- покажи открытые вопросы, варианты и недостающие свидетельства;
- если требуется инвентаризация данных, выполни только разрешённое исследование или запроси
  конкретный недостающий отчёт; не заменяй его обещанием построить отчёт в ходе реализации.

Публикация вопросов и перевод в статус ожидания ответа допустимы только по уже действующим
полномочиям процесса. Автономный режим меняет канал вопроса на эскалацию, но не снимает остановку.
Открытый вопрос нельзя скрывать при последующей перепроверке, сжатии контекста или передаче исполнителю.

## Когда можно продолжить

- Человек явно выбрал исход для всей затронутой области.
- Проверенные факты однозначно определили исход. Если утверждается отсутствие конфликтов,
  указаны исследованные данные и полнота охвата; отсутствие исследования не является доказательством.
- Внутреннее инженерное решение, которое действующий процесс разрешает принимать самостоятельно,
  выбрано и записано как допущение. Это не распространяется на оставленный человеку бизнес-выбор.
- Пользователь явно изменил объём так, что спорный результат в задачу больше не входит.
  Сохрани это решение; самостоятельно сужать задачу до исследования нельзя.

После ответа пересчитай оценку при необходимости и вновь проверь весь список развилок.
Не спрашивай повторно про уже подтверждённое решение.

## Сценарии проверки

| Ситуация | Ожидаемый результат |
|---|---|
| Разные правила объединения данных; выбор обещан на тестировании | Остановка |
| Есть план отчёта и утверждения, но нет выбранного соответствия | Остановка |
| Оба варианта оценены одинаково | Остановка до выбора |
| Старый отчёт назвал вопрос «закрытым для оценки» без ответа | Переоткрыть вопрос |
| Ответ получен только по одной группе данных | Остановиться на оставшейся группе |
| Явный ответ покрывает все случаи | Продолжить |
| Полная проверка подтверждает отсутствие спорных случаев | Продолжить с указанием доказательства |
| Разрешённый внутренний выбор закрыт записанным допущением | Продолжить |
| Пользователь явно оставил в объёме только исследование | Оценить новый объём, не разрешать исключённую реализацию |

Эти сценарии проверяют решения агента по тексту инструкции. Они не создают техническую
блокировку внешней системы релизов и не гарантируют поведение всех будущих прогонов модели.
