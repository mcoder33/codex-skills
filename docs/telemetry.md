# Локальная телеметрия делегирования

`delegation-stats` строит обычные Markdown-заметки Obsidian без community-плагинов. Python 3.11+ и стандартная библиотека; `Europe/Samara` используется для отображения времени. Сбор запускается вручную либо главным агентом после существенной делегированной работы по `model-router`. Демон, cron и внешняя отправка не настраиваются.

```sh
python3 skills/delegation-stats/scripts/collect.py \
  --vault "$HOME/Documents/Obsidian/Codex" --days 7 --api-equivalent
python3 -m unittest discover -s tests -p 'test_delegation_stats*.py' -v
```

Для установленного навыка путь к скрипту: `${CODEX_HOME:-$HOME/.codex}/skills/delegation-stats/scripts/collect.py`. `--codex-home` меняет входной каталог, `--state-dir` — приватный каталог производных данных, `--root-thread` выбирает один корневой поток и потомков. Без `--vault` формируются SQLite и JSON. Default state: `${XDG_STATE_HOME:-$HOME/.local/state}/codex-dialogue-kit/telemetry`. Не используйте общий state для разных Codex home: источник и приватные агрегаты должны иметь один владеющий контур.

## Источники и учёт

Источники — `sessions/**/*.jsonl`, `archived_sessions/**/*.jsonl` и необязательные `threads` / `thread_spawn_edges` в `state_5.sqlite`, открываемом с `mode=ro`. Фильтр окна применяется к timestamp события; filemtime используется только для обнаружения изменений. При расширении окна курсоры автоматически пересчитываются. Неполная последняя строка откладывается до появления newline.

У файла есть курсор inode/size/mtime/offset и состояние контекста. При замене/усечении файл читается заново; прежние нормализованные response-записи сохраняются. Глобальный response ID дедуплицируется с проверкой владельца и usage. Противоречивые дубликаты исключаются целиком. Continuation-файлы одного логического потока объединяются по metadata/usage thread ID, а не по последнему UUID имени файла. Все session_meta обрабатываются по собственному id независимо от порядка; явный usage.thread_id задаёт владельца расхода. При неоднозначном владельце событий используется только однозначная связь turn_id → response owner, иначе время остаётся без атрибуции. Отсутствие parent не доказывает root: тип агента без происхождения выводится отдельной неизвестной группой. Fork baseline, cumulative usage и compaction snapshots не считаются отдельным расходом.

`turn_context` задаёт конфигурацию модели и effort для своего сегмента; при невозможности однозначного восстановления выводится unknown/mixed. Child settings внутри родительского файла не меняют модель родителя. Поле mutable `threads.model` не используется. Запрошенная модель/effort восстанавливается из allowlist аргументов spawn и ответа с canonical task path; неоднозначные попытки не угадываются.

Input включает cached input; output включает reasoning output. Сумма — input + output. Отсутствующие значения — null, а не нули. Legacy token_count без response-level записей отражается как пробел покрытия. `task_complete` означает окончание хода, не успех поручения. Время агентов суммируется по наблюдаемым ходам, может перекрываться и не является elapsed всей группы.

## Деньги

Фактические списания и auth mode неизвестны: локальные события не содержат надёжной квитанции. `--api-equivalent` — отдельный условный расчёт по [API pricing](https://developers.openai.com/api/docs/pricing), проверенному 2026-10-15. Это не расход подписки; [API оплачивается отдельно от включённого использования подписки](https://learn.chatgpt.com/docs/pricing).

| Точное имя модели | Input / 1M | Cached input / 1M | Output / 1M |
| --- | ---: | ---: | ---: |
| gpt-6-luna | $0.10 | $0.01 | $0.50 |
| gpt-6.1-sol | $2.00 | $0.10 | $10.00 |
| gpt-6-astra | $10.00 | $1.00 | $50.00 |

Сценарий включает только ответы с валидным usage, точным именем модели, известным cached input, нулевым cache-write и input ≤128 000. Последнее — консервативное условие сценария, не заявление о тарифном пороге. Формула: `(input − cached) × input_rate + cached × cached_rate + output × output_rate`, делённое на миллион. Reasoning повторно не прибавляется. Cache-write с ненулевым/неизвестным значением исключается; tool fees не включены. Дашборд показывает число исключённых ответов и покрытые токены.

## Приватность, обновление и откат

До SQLite/JSON/Markdown доходят только идентификаторы, безопасные имена моделей/ролей, временные метки, связи и счётчики. Тексты сообщений, prompts, credentials, titles, произвольные аргументы инструментов и результаты не сохраняются. SQLite и JSON — 600, state — 700. Встроенная блокировка допускает одного писателя; исходные Codex файлы никогда не изменяются. Выводимые заметки тоже имеют права 600. Синхронизация vault остаётся настройкой пользователя.

Генерируется только `Телеметрия/Делегирование/Дашборд.md` и вложенный каталог `Агенты`. Сборщик заменяет/удаляет только собственные файлы с маркером `codex-delegation-stats:v1`; остальные заметки не трогает. Обновления файлов атомарны. В дашборде до 50 последних корневых групп; агрегаты охватывают все группы окна. История нормализованных данных в state сохраняется до ручного удаления.

Перед заменой установленного навыка сохраните его копию вне репозитория и сравните локальные изменения. Откат: вернуть прежний каталог навыка. Чтобы полностью пересобрать производные данные, переместите state в резервную копию и выполните сбор снова; источники не удаляйте. Для удаления заметок удаляйте только этот управляемый подкаталог после проверки его содержимого. Репозиторий содержит только код, документацию и синтетические тесты.
