# Состояние навыков и необязательные hooks

Runtime v1 добавляет явное состояние dialogue-explore, dialogue-validate и nasa. Это дополнение к карте и work-memory, а не новая система обобщения истории. Helper не вызывает модель, не сканирует переписки и не меняет навыки автоматически.

## Что установится

- Helper, общий reference и JSON-схема checkpoint внутри dialogue-explore.
- Один отмеченный блок инструкций в каждом из трёх существующих SKILL.md. Остальной установленный текст сохраняется, включая локальные пути и правила.
- По одному обработчику SessionStart, UserPromptSubmit и Stop в пользовательском hooks.json. Existing Serena/work-memory hooks и их порядок сохраняются. Профили агентов, AGENTS.md, config.toml, scheduler и trust-записи не меняются.

В репозитории версии трёх навыков — 0.1.1. При добавлении блока к локально изменённому навыку установщик сохраняет его прежние метаданные; эффективный состав фиксируется hash SKILL.md. Это не полная синхронизация установленного навыка с репозиторием.

Требуется Python 3.11+ и macOS/Linux (flock). На macOS системный python3 может быть 3.9: используйте установленный Python 3.11+ явно. Installer фиксирует абсолютный путь этого интерпретатора в команде hook. При перемещении/удалении Python команду потребуется обновить.

## Просмотр, установка, откат

Из корня репозитория:

```sh
python3 scripts/install_runtime.py --codex-home /absolute/codex-home
python3 scripts/install_runtime.py --codex-home /absolute/codex-home --apply
python3 scripts/install_runtime.py --codex-home /absolute/codex-home --rollback
```

Первый запуск показывает только список целевых файлов. Установка требует наличия всех трёх навыков. Сначала сравните preview и текущие изменения. Состояние установки и резервные копии хранятся приватно в .skill-runtime-install.json в CODEX_HOME (не публикуйте его). При сбое manifest позволяет rollback; не повторяйте незавершённую установку слепо. Повторная установка той же версии идемпотентна. Обновление версии требует rollback/reconcile: локальные правки не перезаписываются.

После установки откройте `/hooks` в целевом клиенте и проверьте три команды с `--package=codex-skills-runtime-v1`. Штатно review/trust необходим для новых определений. Установщик не редактирует hashes доверия и не обходит их. Наличие hooks.json и синтетический запуск команды не доказывают нативный dispatch.

Rollback отказывается затирать изменённые после установки файлы. Для hooks.json удаляет только неизменённые обработчики этого пакета, сохраняя добавления других пакетов. Чтобы временно выключить пакет, отключите его три обработчика через /hooks. Не отключайте весь hooks feature: это затронет общую память и Serena. Не регистрируйте те же команды одновременно в плагине и пользовательской конфигурации; установщик проверяет конфликты в hooks.json и inline hooks config.toml, но не перечисляет все плагины.

## Контракт событий

| Событие | Поведение |
|---|---|
| SessionStart startup/resume/compact | Возвращает только активное состояние точной пары cwd/session_id, если hash карты совпал. Не более 2800 символов: большой снимок заменяется ссылкой на полную карту. |
| UserPromptSubmit | Записывает turn_id и флаг maintenance в отдельный небольшой receipt. Не сохраняет prompt, не подбирает контекст и не активирует навыки. Нужен, поскольку turn_id не всегда доступен агенту через окружение. |
| Stop | Сверяет текущий hash карты с последним checkpoint. Новый ход без изменений не требует записи. Отсутствующая/изменённая карта даёт одно systemMessage на версию несоответствия, без decision:block и continuation. Служебное продолжение общей памяти пропускается. |

clear/fork не наследуют состояние; subagent события с agent_id/agent_type игнорируются. Пользовательский запрос вне активного навыка не получает предупреждений; после завершения используйте finish. Для многозадачного разговора состояние v1 отражает один активный навык: завершайте его перед сменой, данные других обсуждений сохраняются в общей памяти.

Явная активация фиксирует заявление агента и точный hash навыка. Она не доказывает соблюдения протокола. Checkpoint требует уже сохранённую карту, её SHA256 и ожидаемую revision. Карта должна существовать; недоступный vault не маскируется успешным checkpoint. Helper не дописывает Obsidian сам: используйте существующий механизм сохранения и затем укажите его артефакт. Текст предложений, подтверждённых решений и технических проверок формирует агент с источниками.

Ошибки hook видны, но не блокируют работу. Нет сетевых запросов, вызовов моделей, автоматической смены разрешений или ретроспективных правок. Технический журнал ограничен 128 событиями на сессию; приватное состояние не публикуется. Реестр сессий не удаляется автоматически.

## Проверки

```sh
python3 -m unittest discover -s tests
```

Проверки на временных каталогах покрывают изоляцию сессий, stale revision/map, повторные callbacks, ожидание пользователя, clear/fork/subagent, corrupted state, конкуренцию lock, установку/откат и сохранение соседних hooks. Они не измеряют качество диалога. План поведенческого сравнения — [runtime-pilot.md](runtime-pilot.md).

Формат Codex hook: https://learn.chatgpt.com/docs/hooks . Дата проверки документации: 2026-10-16.

Тихий режим: work-memory — владелец общего журнала и обобщения. Runtime навыков хранит только состояние применения и версию карты. Служебная обёртка hook_prompt распознаётся для maintenance receipt. Факт нового turn_id сам по себе не требует checkpoint.
