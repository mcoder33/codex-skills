# Установка и обновление

[К обзору](../README.md) · [Примеры использования](usage.md)

Начните с одного навыка. Профили моделей, Obsidian и hooks подключаются отдельно и не нужны для `adaptive-dialogue`, `clear-communication`, `go-development` или работы с доступным Grafana JSON.

## Подготовка

Нужны Git и клиент Codex с поддержкой навыков. Команды ниже рассчитаны на macOS/Linux и shell; Python 3.11+ нужен для проверок и Python-скриптов, а не для чтения обычного `SKILL.md`.

```sh
git clone https://github.com/mcoder33/codex-skills.git
cd codex-skills
KIT_HOME="${CODEX_HOME:-$HOME/.codex}"
```

Все следующие команды выполняются из корня клона. Для закреплённой версии сначала выберите тег из `git tag --list` и переключитесь на него через `git switch --detach <тег>`. Не копируйте угловые скобки буквально.

В примерах используется каталог навыков `$KIT_HOME/skills`, принятый в этом наборе. Если ваш клиент использует другое расположение, укажите его фактический путь. Механизм обнаружения навыков и интерфейс меняются между версиями: сверяйтесь с [официальной документацией навыков](https://developers.openai.com/codex/skills).

## Один навык

Пример установки `adaptive-dialogue` с отказом от перезаписи существующего каталога:

```sh
SKILL_NAME=adaptive-dialogue
SKILL_DEST="$KIT_HOME/skills/$SKILL_NAME"
mkdir -p "$KIT_HOME/skills"
if [ -e "$SKILL_DEST" ] || [ -L "$SKILL_DEST" ]; then
  echo "Уже существует: $SKILL_DEST. Сначала сравните версии и сохраните копию."
else
  cp -R "skills/$SKILL_NAME" "$SKILL_DEST"
fi
```

Для первого запуска `clear-communication` или `go-development` замените `SKILL_NAME` в этом же примере. Для Go-разработки нужен toolchain и штатные проверки целевого проекта; отдельные модели, Obsidian и книга не требуются.

Копируйте каталог целиком: ссылки из `SKILL.md` могут вести в `references/`, `scripts/` или другие вложенные каталоги. Для другого самостоятельного навыка замените `SKILL_NAME`.

Откройте новый сеанс Codex, убедитесь, что навык есть в доступном списке, и отправьте пример из [руководства использования](usage.md). Само наличие файла на диске не доказывает, что клиент его обнаружил.

## Какие зависимости нужны

| Навык или возможность | Что добавить |
| --- | --- |
| `adaptive-dialogue`, `clear-communication`, `go-development` | Для базового вызова достаточно каталога навыка |
| `grafana-dashboards` | JSON или доступ к Grafana и данным; UI/renderer для визуальной проверки |
| `dialogue-explore` и `dialogue-validate` | Установите оба каталога: validate ссылается на контракт внутри explore |
| `nasa` | Собственные справочники входят в каталог; для сохранения карты укажите разрешённое хранилище |
| `model-router` | Поддержка подагентов, доступные модели, разрешение на делегацию и профили ниже |
| `delegation-stats` | Локальные журналы Codex, Python и отдельная [настройка статистики](telemetry.md) |
| `session-retrospective` | Два dialogue-навыка, журналы, исполнители и независимое ревью; [условия применения](retrospective.md) |
| Runtime/hooks | Отдельная [установка runtime](skill-runtime.md) и совместимая версия клиента |

## Карта обсуждений в Obsidian

1. Установите `dialogue-explore` и `dialogue-validate`, повторив команду копирования для каждого.
2. Выберите каталог, в котором разрешаете сохранять карты, например `$HOME/Documents/Obsidian/Codex-Dialogue`.
3. Укажите **абсолютный путь** в запросе или применимых инструкциях: «Сохраняй карту этого обсуждения в …». Shell-переменная сама по себе не передаёт этот путь агенту.
4. Для знакомства скопируйте содержимое [vault-template](../vault-template/Карта%20обсуждений.md) в новый пустой каталог. В существующем vault добавляйте только отсутствующие файлы, сохраняя реальные заметки.
5. В Obsidian выберите «Открыть папку как хранилище», откройте `Карта обсуждений`, затем граф. Шаблон — вымышленный пример; для своей задачи создайте отдельную тему.

Карта остаётся обычными Markdown-файлами. Без доступного хранилища обсуждение может продолжаться в чате, но нельзя считать его сохранённым в Obsidian. Появление файла не открывает граф автоматически.

## Постоянное применение

Явного вызова `$имя-навыка` достаточно для первого запуска. Если нужен режим по умолчанию, вручную добавьте соответствующий фрагмент в **фактически загружаемый** `AGENTS.md`:

| Режим | Фрагмент | Что подставить |
| --- | --- | --- |
| Ясное изложение | [clear-communication.fragment.md](../config/clear-communication.fragment.md) | `{{CODEX_HOME}}` — абсолютный путь каталога настроек |
| Адаптация общения | [adaptive-dialogue.fragment.md](../config/adaptive-dialogue.fragment.md) | `{{CODEX_HOME}}` — абсолютный путь каталога настроек |
| Разработка Go | [GO-DEVELOPMENT.fragment.md](../config/GO-DEVELOPMENT.fragment.md) | `{{SKILL_PATH}}` — полный путь установленного `SKILL.md` |
| Диалог, карта **и маршрутизация** | [AGENTS.fragment.md](../config/AGENTS.fragment.md) | `{{CODEX_HOME}}` и `{{DIALOGUE_VAULT}}` |

Общий dialogue-фрагмент включает политику делегации. Если нужна только карта, укажите путь и правила применения двух dialogue-навыков отдельно; не добавляйте весь фрагмент автоматически.

Перед слиянием сохраните копию файла вне репозитория. Сохраните остальные инструкции; при обновлении заменяйте соответствующий блок `BEGIN/END`, не добавляя дубль. Шаблонные `{{…}}` не подставляются автоматически. Если используется `AGENTS.override.md`, проверьте, какой файл действительно читает клиент; не создавайте override ради установки.

## Модели и подагенты

Этот шаг нужен для маршрутизации. Скопируйте четыре TOML-профиля из каталога `agents/` в `$KIT_HOME/agents`, предварительно проверив совпадающие файлы. Затем вручную слейте [config/agents.toml](../config/agents.toml) с существующим `$KIT_HOME/config.toml`.

Не создавайте второй `[agents]` и повторные таблицы `agents.routed-*`. Сохраните чужие профили и лимиты. `config_file` в этом фрагменте задаёт путь относительно каталога конфигурации; проверьте поддержку в своём клиенте.

| Профиль | Модель в файле | Reasoning effort | Работа |
| --- | --- | --- | --- |
| `routed-scout` | `gpt-6-luna` | `high` | Узкий сбор фактов, только чтение |
| `routed-worker` | `gpt-6.1-sol` | `medium` | Реализация в выделенной области |
| `routed-reviewer` | `gpt-6.1-sol` | `high` | Независимое ревью, только чтение |
| `routed-expert` | `gpt-6-astra` | `low` | Разбор противоречивых свидетельств, только чтение |

Это содержимое профилей, а не гарантия доступности моделей в вашем аккаунте. Если модель недоступна, выберите поддерживаемое соответствие и согласованно обновите профиль и таблицу выбора в установленном `model-router`. Не выдавайте запрошенную модель за фактически запущенную.

Проверка синтаксиса и путей, Python 3.11+:

```sh
python3 - "$KIT_HOME/config.toml" <<'PYCODE'
import pathlib, sys, tomllib
config = pathlib.Path(sys.argv[1])
data = tomllib.loads(config.read_text())
for name in ('routed-scout', 'routed-worker', 'routed-reviewer', 'routed-expert'):
    profile = config.parent / data['agents'][name]['config_file']
    tomllib.loads(profile.read_text())
print('TOML и пути проверены; фактический запуск моделей нужно проверить отдельно.')
PYCODE
```

Главный агент ведёт разговор и координацию; исполнитель получает ограниченный контракт и не делегирует рекурсивно. Предел набора — до трёх подагентов, но фактический лимит среды может быть ниже. Настройки не отменяют ограничения текущей сессии.

## Обновление и откат

1. Сохраните копии затрагиваемых установленных каталогов, `AGENTS.md` и `config.toml` вне репозитория. Запишите текущий тег или commit.
2. Получите нужную версию репозитория. Сравните её с установленными файлами, например `diff -ru skills/adaptive-dialogue "$KIT_HOME/skills/adaptive-dialogue"`.
3. Перенесите изменения, сохранив локальные правки. Не копируйте новый каталог поверх старого без сверки: так могут остаться удалённые в новой версии файлы.
4. Фрагменты конфигурации слейте повторно вручную. Не заменяйте рабочий vault шаблоном.
5. Откройте новый сеанс и повторите свой короткий сценарий использования.

Для отката восстановите сохранённые версии только затронутых файлов. Если после копии появились другие изменения конфигурации, отмените лишь строки этого набора. Для удаления уберите добавленные блоки, таблицы и профили, затем каталоги выбранных навыков после проверки локальных правок. Карты и пользовательские данные сохраняйте. Runtime имеет собственную процедуру отката в [руководстве](skill-runtime.md).

### Переход со старых навыков

В этой ветке прежний `cohesive-development` заменён специализированным `go-development`; старое имя здесь приведено только для миграции. Сначала сохраните копию старого каталога и локальные правки, затем установите новый навык целиком с проверкой совпадений из раздела «Один навык». Проверьте новый сценарий до удаления старой копии.

В своих активных workflows замените прежний вызов `$cohesive-development` на `$go-development` только для Go-задач. В `AGENTS.md` замените старый блок `BEGIN/END COHESIVE DEVELOPMENT` на [GO DEVELOPMENT](../config/GO-DEVELOPMENT.fragment.md), подставив новый `{{SKILL_PATH}}`. Остальные инструкции сохраните. Общий аудит других языков больше не является назначением этого навыка.

Прежний `execute-handoff` и его фрагмент удалены из набора: автоматической передачи по команде «делай» и выбора по таймеру больше нет. Удалите только его старый блок `BEGIN/END EXECUTE HANDOFF` из своей конфигурации; перед удалением каталога сохраните локальные правки. Для явно разрешённой маршрутизации используйте `model-router`. Эти действия выполняет владелец установки; обновление публичного репозитория не меняет локальную конфигурацию автоматически.

## Если что-то не работает

| Симптом | Что проверить |
| --- | --- |
| Навык не виден | Правильный каталог клиента, наличие `SKILL.md`, отсутствие лишнего уровня вложенности; затем новый сеанс |
| Навык виден, но не применяется | Вызовите его явно; проверьте, что запрос соответствует назначению и нет конфликтующих инструкций |
| Validate не находит контракт карты | Оба dialogue-каталога должны лежать рядом и быть скопированы целиком |
| Карта есть в чате, но её нет в Obsidian | Абсолютный путь, право записи и фактическое наличие файла; открыт ли именно этот vault |
| Ошибка TOML | Дубли таблиц/ключей, корректность слияния, пути к профилям; выполните проверку выше |
| Модель или делегация недоступна | Возможности клиента, аккаунта и ограничения сессии; профиль не включает отсутствующую возможность |
| Hooks не срабатывают | Следуйте [проверке совместимости](hooks-compatibility.md); обычная установка навыка hooks не включает |
| Статистика не совпала со счётом | Отчёт описывает локальные события, не биллинг; см. [формулы и ограничения](telemetry.md) |
